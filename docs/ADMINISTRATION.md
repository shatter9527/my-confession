# 管理员与令牌

后台入口为 `/pages/admin.html`。载入令牌后，顶部显示当前管理员；导航里的「管理员」可跳到管理列表，「操作日志」可查看和筛选记录。

## 日常操作

- **新增**：填写名字，点击「生成新令牌」，复制生成的令牌交给对应管理员。
- **改名**：只改变显示名字，管理员 ID 不变。日志保留操作当时的名字。
- **换令牌**：旧令牌立即失效，新令牌只在此次操作结果中展示。为自己换令牌时，当前浏览器自动采用新令牌，并同步同源后台标签页。
- **停用**：令牌立即失效，管理员记录和日志保留。不能停用当前使用的管理员。
- **启用**：为停用的管理员生成全新令牌，不恢复旧令牌。
- **清除本机口令**：同时清除浏览器保存值和页面内存，停止待处理请求、关闭管理面板，并同步同源后台标签页；这不会吊销服务器上的令牌。

审核台和正文编辑页共用登录状态。令牌被停用后，下一次管理请求会清空失效的登录状态。两个页面仍使用 `x-admin-token` 请求头，令牌明文保存；没有改成 Cookie 登录。

操作日志可按操作者筛选，每次加载 50 条，可继续加载更早记录。最多保留最近 2000 条；管理员新增、改名、换令牌、停用/启用和审核设置变更与对应日志在同一 SQLite 事务中提交。

## 首次安装及旧版升级

管理员、令牌、三个审核开关和操作日志现在保存在 `data/app.db` 中。

- 首次安装且没有旧配置时：生成默认管理员，在启动终端显示一次初始令牌；重启不重复打印。
- 升级旧部署：首次启动自动读取旧 `config.json` 的 `adminToken` 或 `adminTokens`，保留令牌、管理员 ID、名字和时间信息，并迁移审核开关。
- 导入完成后：数据库保存迁移标记，后续启动不再读取旧配置。修改或重新放入旧配置不会恢复已停用的令牌。
- 旧配置有语法、结构、重复 ID/名字/令牌等错误时：启动失败并提示原因；不会覆盖原文件或重新生成管理员。修复旧配置后可重启再次导入。
- 原 `config.json` 不会被自动修改或删除；它只是升级输入，不再是运行时配置。Docker 中的 `/app/config.json` 链接仍用于读取旧卷的 `/app/data/config.json`。

**升级前**运行 `node backup.js` 并保存旧 `config.json`。部署应包含 `lib/admin-store.js`、`js/admin-client.js` 及更新的两个后台页面。上线后使用已有令牌登录，确认管理员名单和审核开关。

## 备份、恢复和本机找回

`node backup.js` 的 SQLite 快照现在包含管理员、令牌、审核开关和日志；旧版本生成的数据库快照仍需配合旧 `config.json` 才能完整迁移。Docker 内使用 `docker compose exec my-confession node backup.js`。

恢复数据库时先停止服务，再按现有备份流程恢复。恢复旧快照会恢复**快照时刻**的令牌和停用状态，应核对恢复后的管理员列表。回退到旧版代码时，应同时恢复升级前的数据库和配置；旧版代码无法读取新表里的管理员变更。

若忘记保存初始令牌，有服务器本机权限的维护者可在项目目录查询有效管理员（命令会显示完整令牌，请勿把输出贴到公开日志）：

```bash
node admin.js token
# Docker 部署：
docker exec my-confession node admin.js token
```

只看管理员名单、不显示令牌可用 `node admin.js list`。命令优先读取新版数据库，也兼容旧 `config.json`（包括 Docker 软链接）；不会修改数据。若只有旧数据库而配置已丢失，命令会明确提示无法还原旧令牌。

访问 `/api/version` 可核对部署版本：本次为 `2026.10.18-admin4`。启动日志也会显示版本和构建指纹。若该接口返回 404，或容器中没有 `admin.js`，需要核对实际服务的容器、镜像和源码挂载。命令行更新使用原 Compose 项目目录下的 `docker compose up -d --build`；NAS 图形界面步骤见 [部署指南](DEPLOYMENT.md#docker-nas)。

## 实现与测试

`lib/admin-store.js` 管理认证、管理员生命周期、旧配置迁移和事务；`server.js` 保留 HTTP 路由；`js/admin-client.js` 统一两个后台页面的请求和登录状态。

`npm run test:unit` 用临时 SQLite 数据库验证迁移、写入失败回滚、重启、稳定身份与日志分页。`npm test` 先运行这些测试，再运行桌面和手机浏览器回归，包括清除口令、跨标签页同步、旧请求返回、令牌轮换和停用。

人物页的改动见 [当前版本更新说明](releases/2026.10.18-admin4.md)。
